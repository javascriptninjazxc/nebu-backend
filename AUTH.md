# Авторизация

PostgreSQL 17 + Sequelize ORM (`@nestjs/sequelize`, `sequelize-typescript`). Схема меняется миграциями; `synchronize` отключён. DTO используют `class-validator` и `class-transformer`; логин приводится к нижнему регистру, пароль не изменяется.

## Локальный запуск

1. Скопировать `.env.example` в `.env`, задать собственный `POSTGRES_PASSWORD` и соответствующий `DATABASE_URL`.
2. `docker compose up -d postgres` — PostgreSQL на `127.0.0.1:15432`, данные в named volume.
3. `npm run db:migrate` — транзакционная миграция с журналом и advisory lock. Повторный запуск безопасен.
4. `npm run start:dev` — API на `127.0.0.1:3001/api`.

Nuxt обращается к Nest через серверный `NUXT_BACKEND_BASE` (по умолчанию `http://127.0.0.1:3001/api`). Для определения IP клиента установить одинаковые случайные `AUTH_PROXY_SECRET` в backend и `NUXT_AUTH_PROXY_SECRET` в Nuxt. Эти переменные не public. Без них лимит применяется к IP непосредственного соединения. Произвольные `X-Forwarded-For` не принимаются. При размещении за reverse proxy отдельно настройте доверенную передачу адреса; не публикуйте Nest напрямую без необходимости.

## Контракт Nest API

| Метод | Путь               | Тело / результат                                                                                |
| ----- | ------------------ | ----------------------------------------------------------------------------------------------- |
| POST  | `/api/auth/quick`  | `{ "promo": "OPTIONAL" }` → 201, `{ user, token, expiresAt, credentials: { login, password } }` |
| POST  | `/api/auth/login`  | `{ "login": "nebi_...", "password": "..." }` → 200, `{ user, token, expiresAt }`                |
| GET   | `/api/auth/me`     | `Authorization: Bearer TOKEN` → `{ user: { id, login } }`                                       |
| POST  | `/api/auth/logout` | `Authorization: Bearer TOKEN` → 204; токен отзывается                                           |

Ошибки: 400 — DTO, 401 — неправильные данные / сессия истекла, 429 — лимит попыток. Swagger: `/api/docs` в development.

Случайный пароль возвращается только при создании аккаунта. Хранится scrypt-хеш с индивидуальной солью, токены сессий — SHA-256-хеши. Сессия действует 7 дней и переживает перезапуск Nest. Создание пользователя и сессии — одна транзакция. Промокод сохраняется как атрибут регистрации; начисление бонусов этим модулем не выполняется.

Nuxt `/api/auth/*` — same-origin шлюз: не отдаёт токен JavaScript, хранит его в HttpOnly / SameSite=Lax cookie (Secure на HTTPS), проверяет Origin на мутациях и ставит `Cache-Control: no-store`. Cookie и Authorization браузера не пересылаются произвольным URL. Автоповторов POST нет. Пароль находится только в экране результата и скачиваемом пользователем файле, не в localStorage. При потере ответа регистрации пароль восстановить нельзя: функциональность восстановления пароля пока не реализована.

Лимиты хранятся в PostgreSQL, общие для процессов Nest: 10 регистраций/IP/мин, 60 входов/IP/мин, 10 входов/логин/мин. Старые лимиты и истёкшие сессии очищаются при обращениях.

## Проверки

Указать отдельный `TEST_DATABASE_URL` (не равный рабочему DATABASE_URL), создать эту тестовую БД и применить к ней миграции. `npm run check` проверяет lint, типы, unit, HTTP E2E на PostgreSQL и сборку. HTTP E2E очищает таблицу лимитов **тестовой** базы.

Для UI E2E сначала `npm --prefix backend run build`, затем сборка Nuxt и `npm run test:e2e`. Playwright поднимает отдельный Nest на 3004 с TEST_DATABASE_URL, применяет миграцию и запускает Nuxt на 3100. Созданные аккаунты остаются только в тестовой БД.

Перед production нужны управляемый PostgreSQL, резервное копирование, HTTPS и настоящие секреты подключения. Социальные провайдеры и восстановление доступа этим изменением не подключены.
