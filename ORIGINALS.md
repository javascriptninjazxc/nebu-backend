# Серверные Originals и общие Mini/Mega

Реализовано 2026-09-18. NestJS, PostgreSQL, Sequelize, Socket.IO. Валюта **DEMO**, без пополнения и вывода. Nuxt использует серверные результаты; браузер отвечает за ввод и анимацию.

## Запуск и данные

1. Настроить backend/.env по AUTH.md и DICE.md.
2. Выполнить npm run db:migrate в backend (миграции 001–003).
3. npm run build и npm run start:prod в backend.
4. Для Nuxt: NUXT_BACKEND_BASE — Nest /api; NUXT_PUBLIC_DICE_SOCKET_BASE — origin Nest; общий AUTH_PROXY_SECRET только в закрытом окружении. Разрешить origin Nuxt через DICE_WS_ORIGINS.
5. В production нужны HTTPS/WSS и настроенный origin. Секреты и session token не передаются игровому JS.

Имя namespace /dice и таблиц dice_wallets/dice_entries сохранено ради совместимости. Это общий транспорт и общий кошелёк Dice, «Сердца леса», «Тайников» и джекпотов. Начальные 10 000 DEMO выдаются аккаунту один раз. Старые балансы Dice не сбрасываются. Локальные раунды прежней версии без серверной записи не импортируются как достоверные деньги.

003-originals добавляет original_rounds, original_progress, original_commands, jackpot_periods, jackpot_participants, jackpot_contributions, jackpot_outbox и источники операций в общем журнале. Автоматическая синхронизация схемы ORM выключена; нужны миграции.

## WS-протокол

HttpOnly-сессия → POST /api/auth/ws-ticket в Nuxt → одноразовый билет (30 секунд) → Socket.IO /dice с auth.ticket. Транспорт только websocket. Все команды требуют requestId UUIDv4. Strict DTO через class-transformer/class-validator отклоняют лишние поля, неверные типы, null, чужие ID. Сессия повторно проверяется внутри каждой транзакции.

| Событие                                                 | Дополнительные поля                      |
| ------------------------------------------------------- | ---------------------------------------- |
| forest.start                                            | stakeMinor: строка сотых фишки           |
| forest.open, forest.charge, forest.risk, forest.cashout | roundId, expectedVersion                 |
| forest.spin                                             | roundId, expectedVersion, target: 0–2    |
| caches.start                                            | stakeMinor, cardIndex: 0–5               |
| caches.reveal                                           | roundId, expectedVersion, cardIndex: 0–5 |
| caches.cashout                                          | roundId, expectedVersion                 |
| forest.sync, caches.sync                                | необязательный roundId                   |
| jackpots.sync                                           | необязательный drawId                    |
| jackpots.reveal                                         | drawId, expectedVersion, cardIndex: 0–2  |
| jackpots.claim                                          | drawId, expectedVersion                  |
| *.commandStatus                                         | operationId исходной команды             |

ACK: { ok:true, requestId, data } или { ok:false, requestId, error:{code,message,retryable} }. Точные типы: backend/src/games/contracts.ts, shared/types/originals.ts. Суммы — десятичные строки в сотых фишки. Ставки 10–100 000 целых фишек. Случайность — node:crypto, не Math.random и не браузер.

Один активный раунд на игру/аккаунт. Разные игры могут иметь активные раунды, но списывают один кошелёк под общей блокировкой аккаунта. Версия раунда предотвращает конфликт двух вкладок. requestId + хеш тела возвращают тот же результат при повторе; другое тело с тем же ID отклоняется. Запись команды, ставка, выплаты и журнал фиксируются одной транзакцией.

Сервер никогда не возвращает раскладку закрытых карт. caches.start открывает только первую выбранную карту, caches.reveal — только выбранную карту; sync восстанавливает уже открытые. Нет endpoint принудительного исхода, смены RNG или сброса баланса.

## Сердце леса — forest-1

16 равных секторов: 5 монет, 4 кристалла, 2 ключа, 5 банкротов.

- Монета: ×1,4; можно забрать или один раз рискнуть с шансом 50% на удвоение / 50% на ноль.
- Кристалл: ×0,5 сразу; 5% ставки этого выпадения накапливается в коллекции. Каждый пятый кристалл выплачивает накопленное; доли фишки переносятся в следующий цикл.
- Ключ: открыть сердце (одна из трёх целей). Совпадение ×9, промах ×0,25. Заряд ключа: 50% переход к сердцу с множителем ×2, 50% потеря ставки.
- Банкрот: ноль.

Теоретический RTP до округлений: 97,0833% при завершении раундов и получении бонусов коллекции. Обычные выплаты округляются вниз до целой фишки, поэтому фактический расчётный RTP зависит от ставки и ниже этой верхней оценки. Риск не увеличивает математическое ожидание.

Ставка, фаза, ключ, выбранная цель, предложение и коллекция сохраняются на сервере. Финальный результат начисляется в транзакции до анимации. complete() на клиенте лишь завершает показ; закрытие вкладки не отменяет начисление.

## Тайники Неби — caches-network-1

Шесть карт, ровно три сокровища. Сервер создаёт неизменяемую скрытую колоду до первого открытия. Ставка списывается один раз вместе с первым кликом.

| Найдено | Выплата со ставкой | Вероятность достичь |
| ------- | ------------------ | ------------------- |
| 1       | ×1,92              | 1/2                 |
| 2       | ×4,8               | 1/5                 |
| 3       | ×19,2              | 1/20                |

После первой/второй находки доступен выкуп; следующая пустая карта обнуляет находку. Третья находка выплачивается автоматически. Базовый RTP 96% при любом из трёх сроков выкупа. Выплаты точны до сотой фишки, включая ставку 11 → 21,12.

С каждой принятой ставки 1% идёт в Mini и ещё 1% в Mega. Это распределение внутри ставки, не дополнительное списание. Общий долгосрочный RTP 98% **при полном получении зарезервированных джекпотов**. Старый персональный банк и независимый шанс совпадения после трёх сокровищ удалены. В текущей версии банки пополняет только эта игра.

## Mini/Mega

- Mini закрывается в начале каждого часа; Mega — в 00:00 Москвы (UTC+3).
- Принимается серверное время PostgreSQL, один timestamp для обоих взносов. Периоды полуоткрытые: начало включено, конец исключён.
- Веса участников равны сумме принятых ставок за период. Проигрыш или ранний выкуп не отменяют участие. Онлайн-присутствие не требуется.
- Сервер выбирает ровно одного победителя криптографическим выбором по bigint-весам без modulo bias. Победитель и сумма фиксируются до раскрытия карт.
- У победителя три Неби, у остальных три несовпадающих символа. Карты показывают уже определённый результат и не влияют на шанс.
- После трёх подтверждённых открытий победитель отправляет claim. Сервер проверяет пользователя, сохранённые открытия, версию и победителя, затем атомарно начисляет приз и записывает журнал.
- Приз хранится до получения, без срока сгорания. Новые ставки идут в новый период и не меняют старый приз. Даже повторные запросы из двух вкладок не создают повторное начисление.
- Пустой период без ставок не создаёт победителя и искусственного банка.

Scheduler каждые 5 секунд и при запуске завершает пропущенные периоды (пачки до 100). PostgreSQL advisory lock предотвращает два розыгрыша и конфликт с последним взносом; работает при нескольких процессах Nest. Outbox хранит приглашение вместе с фиксацией победителя. Доставка через jackpots.changed; в событии только eventId. Клиент запрашивает персональный snapshot. Уведомление может дублироваться, данные и начисления — нет.

Без Redis-adapter push приходит клиентам того процесса, который прочитал outbox. Клиент также синхронизируется каждые 15 секунд при видимой странице и при переподключении: другие узлы и потерянный push восстанавливаются этим путём. Это периодическое обновление, не гарантия мгновенной рассылки всем узлам.

pending возвращает до 20 участий и hasMore; после завершения они освобождают место следующим. Выбранный drawId позволяет восстановить открытое окно, включая уже выплаченный приз.

## Восстановление и ограничения

При неизвестном результате клиент сохраняет ID/тело команды в sessionStorage, блокирует новые действия, сверяет commandStatus и sync. Мутации автоматически не переотправляются. Пользователь может явно повторить исходную команду. Старая версия баланса не перезаписывает новую; общий useGameBalance отражает приз джекпота на странице любой игры.

Лимиты общего транспорта: 4 соединения аккаунта, 15 команд/секунду, максимум 4 КиБ входящего кадра, защита от параллельных незавершённых сообщений и IP-handshake flood. Открытая игровая страница использует два сокета: игра и общие джекпоты. Производственные лимиты и настройки описаны в DICE.md.

Это серверная DEMO-реализация. Нет платежей, вывода, проверенной нагрузочной ёмкости для 10 000 одновременных игроков, публичного provably-fair протокола или внешней сертификации RNG. Журнал и requestId сейчас не очищаются по TTL: политика хранения и архивирования должна сохранять защиту от повторных начислений.

Browser integration: Playwright desktop/mobile, авторизация, Dice, обе игры, сетевые карты/claim/reload/offline, восстановление WebGL и коллекции. backend/scripts/e2e-fixture.mjs используется только процессом тестов с отдельной TEST_DATABASE_URL, не импортируется приложением и не создаёт тестовых маршрутов. Управляемые результаты RNG проверяются через DI в backend/test/originals.e2e-spec.ts; production RNG не имеет переключателя.
